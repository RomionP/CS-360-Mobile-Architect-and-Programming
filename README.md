Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

A:The requirements to meet user needs was to make an app that allows users to create a account, sign back in, add their daily weight, add a goal weight, and have a SMS notifier for when the user meets their goal. The app was designed to let users enter, update, delete, and view their daily weight entries. The user can set a goal weight in which it congratulates the user for meeting their goal weight. The app is designed for those who want to keep track of their daily weight like athletes or any medical purposes.

What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

A: The login screen addresses the issue of letting the user create a account, sign back in or use the app without a account. A permission screen is necessary for letting SMS messages be sent to the user for meeting their goal. The main dashboard is where users enter weights, set the goal, view entered weights and see your overall progress. The next screen lets users view their entered weights and the final screen is for changing the settings like SMS permissions within the app. I kept users in mind with my UI by keeping it simple with a focus more around accessibility and functionality. My designs were successful because it meet user needs without overcomplicating the functionality and design.

How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

A: I approached the process of coding my app by making sure my code is manageable and reusable. I wanted my code to follow more CRUD operations so it could meet required functionality. This strategy can be applied to future projects especially ones that pertain to persistent data since CRUD operations supports this type of architecture.

How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

A: I ensured the code was functional by the use of unit testing throughout the app creation process. This is important as it can be expensive to fix errors in the finished product, so it's better to test functionality throughout the project. Unit testing reveled errors and misspelled strings that would needed to be fixed in the final product if I didn't test through tout the project.

Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

A: I had to innovate the challenge of accessibility by adding a option to use the app without a account. Towards the end of the project there was only the option of using the app if you had a account or create one. I thought that maybe some users want to try the app's functionality without too much commitment, so I added a option to continue to the app without a account. The option is located on the login screen and is labeled as continue as guest. 

In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?

A: The specific component of my mobile app that I was successful in was my overall design of my login and dashboard screen as it lets the user have 3 options of continuing to the app, as well as having all the user's entered data on dashboard with time stamps. The user can also edit and delete entries and see the difference of a previous weight and the current weight entered. The progress bar is interactive as it moves over or under the goal weight based on the the user's entered weight. I've had some experience with full stack applications, but this has gave me more experience I can apply to my career as a software engineer.
